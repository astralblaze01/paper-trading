# VANTAGE 다음 UI/UX 개선 작업 요청서

이 문서는 현재 모의투자 서비스의 다음 개선 작업을 위한 구현 지시서다. 기존 회원가입, 로그인, 지갑, 거래, 환전, 관리자, 데이터 공급자 연동은 유지한다. 실제 돈이나 실제 증권 주문은 절대 수행하지 않는다.

## 작업 원칙

- 기존 기능을 무작정 삭제하거나 DB 데이터를 초기화하지 않는다.
- 모바일 브라우저를 우선으로 설계하고 데스크톱에서도 자연스럽게 보이게 한다.
- 가격·등락률·수익률은 공급자 데이터와 동일한 기준으로 표시한다.
- `+` 등락률은 빨간색, `-` 등락률은 파란색, `0`은 중립색으로 전역 통일한다.
- 숫자·통화·등락률은 한눈에 읽히도록 글자 크기와 간격을 확보한다.
- 외부 API가 제공하지 않는 값을 하드코딩하거나 실시간이라고 표시하지 않는다.
- 관리자 전용 정보는 일반 사용자 화면과 API 응답에서 노출하지 않는다.

## 1. 서비스 이름 변경

`Paper Harbor`와 기존 브랜드 표기를 새 이름으로 교체한다. 새 이름은 구현 시 하나로 확정하고 다음 위치를 모두 일관되게 변경한다.

- 로그인 화면, 헤더, 푸터
- 브라우저 `<title>`과 접근성 문구
- 관리자 화면과 이메일이 있다면 이메일 문구
- README와 사용자 안내 문구
- localStorage 키는 기존 사용자의 관심종목·최근 종목이 사라지지 않도록 호환 키를 유지하거나 migration한다.

브랜드 이름은 코드에 여러 번 하드코딩하지 말고 설정/상수로 관리한다. 기존 `ASTER` 표기도 새 브랜드로 정리한다.

## 2. 시장 탐색 모바일 화면

일반 사용자는 종목명, 현재가, 등락률, 거래대금, 거래량만 빠르게 읽을 수 있어야 한다.

일반 사용자 시장 탐색 목록에서 다음 열은 숨긴다.

- 종목 코드
- 시세 시각
- 데이터 상태

관리자 계정으로 로그인했을 때만 상세 진단 정보를 표시한다.

- 종목 코드
- 시세 시각
- 데이터 공급자와 데이터 상태
- 지연/오래된 시세 여부

관리자 표시도 모바일에서 표가 깨지지 않도록 행을 접거나 상세 영역으로 보여준다. 일반 사용자의 목록에는 기술적인 공급자 문구를 섞지 않는다.

각 종목 행의 모바일 기본 순서는 다음과 같다.

```text
관심등록   순위
종목명     현재가
           등락률
거래대금   거래량
```

종목명은 가장 크게, 현재가는 두 번째로 크게 표시한다. 거래대금·거래량은 보조 정보로 표시한다. 코드 대신 종목명에 집중할 수 있게 한다.

## 3. 종목 상세 가격과 등락률 배치

종목 상세 화면에서 등락률을 가격 옆에 길게 붙이지 않는다. 다음처럼 가격과 등락률을 별도 시각 블록으로 배치한다.

```text
종목명
현재가
전일 대비 금액       전일 대비 등락률
```

요구사항:

- 현재가는 가장 큰 숫자
- 전일 대비 금액과 등락률은 같은 색상 체계 사용
- 상승은 빨간색, 하락은 파란색, 보합은 중립색
- 가격과 등락률이 좁은 모바일 화면에서도 줄바꿈되어 겹치지 않음
- `+`와 `-` 부호를 명확하게 표시
- `change_pct`가 없으면 임의 계산하지 않고 `—` 표시

## 4. 전체 통화 표시 선택

시장 탐색에서만 통화 선택이 적용되는 현재 구조를 제거하고 로그인 사용자 화면 전체에 동일한 표시 통화 설정을 적용한다.

지원 선택지:

- 거래 통화
- 원화 KRW
- 달러 USD

다음 화면 모두 같은 전역 선택값을 사용한다.

- 시장 탐색
- 종목 상세 현재가
- 차트
- 주문 패널의 참고 금액
- 포트폴리오 평가금액·손익
- 랭킹 평가금액·손익
- 관심종목
- 공개 포트폴리오

주의사항:

- 실제 지갑 차감·입금 통화와 주문 결제 통화는 항상 명확히 표시한다.
- 표시 통화 변경은 화면 표시만 바꾸며 거래 원장과 DB 값은 바꾸지 않는다.
- USD/KRW 환율 기준 시각을 전역 설정 안내에 표시한다.
- 차트의 과거 수익률을 현재 환율로 환산하는 경우 그 사실을 표시하고 과거 환율 수익률이라고 부르지 않는다.
- 환율을 사용할 수 없으면 다른 통화 환산을 `—` 또는 `환율 확인 대기`로 표시한다.

## 5. 차트의 기간별 가격 변화

기간 버튼을 유지한다.

```text
1D | 1W | 3M | 1Y | 5Y | ALL
```

각 기간을 선택했을 때 차트만 보여주지 말고 기간 요약을 함께 표시한다.

```text
1W
시작 가격 → 현재 가격
변화 금액
변화율
기간 시작일 ~ 종료일
```

요구사항:

- 기간 시작 종가와 마지막 종가를 비교한다.
- 변화 금액과 변화율 모두 표시한다.
- 상승이면 빨간색, 하락이면 파란색, 보합이면 중립색
- 차트 선, 기간 요약, tooltip의 상승/하락 색상을 동일하게 한다.
- hover/touch/키보드 이동 시 해당 시점 가격과 시작점 대비 변화 금액·변화율을 표시한다.
- 데이터가 일부만 제공되면 실제 제공 범위만 표시하고 전체 기간이라고 가장하지 않는다.
- 차트 데이터가 없으면 빈 차트에 가짜 가격을 그리지 말고 원인과 재시도 방법을 표시한다.

## 6. 주문 패널 단순화와 수량 비율 선택

사용자가 주문 전에 이해하기 어려운 `예상 금액` 중심 문구를 줄이고, 주문 수량 선택을 쉽게 만든다.

### 주문 방식

- 시장가 주문만 제공한다.
- 지정가 주문 UI, 지정가 입력값, 지정가 API 진입점을 제거한다.
- 기존 미체결 지정가 주문 데이터가 있다면 삭제하지 말고 관리자/마이그레이션 정책을 먼저 정한다.
- 시장가 주문은 실제 체결 시점의 서버 시세와 잔액을 다시 검증한다.

### 수량 빠른 선택

매수 화면에 다음 버튼을 제공한다.

```text
최대 | 50% | 25% | 10% | 5%
```

정의:

- 매수: 현재 주문 가능 현금으로 살 수 있는 최대 수량을 기준으로 비율을 계산한다.
- 매도: 현재 보유 수량을 기준으로 비율을 계산한다.
- 수량은 종목별 주문 단위에 맞춰 내림한다.
- 1주 미만이 되면 0주로 표시하고 주문을 막는다.
- 수수료·세금·환율·잔액을 포함한 서버 authoritative 계산을 사용한다.
- 화면 계산과 실제 체결 계산이 다르면 서버 계산을 우선한다.

주문 패널에는 다음만 간결하게 표시한다.

- 보유 현금 또는 보유 수량
- 선택 수량
- 거래 통화 기준 체결 예상 금액
- 수수료·세금
- 주문 후 예상 잔액 또는 잔여 수량
- 매수/매도 버튼

`예상 금액`이라는 모호한 제목 대신 `체결 금액 참고`, `수수료`, `주문 후 잔액`처럼 의미가 분명한 문구를 사용한다.

## 7. 랭킹 자동 갱신과 전역 색상 통일

이번 요청에서는 기존의 30분 랭킹 갱신 요구를 **10초 화면 갱신 요구로 변경**한다.

- 랭킹 화면을 열어 둔 동안 10초마다 랭킹 API를 확인한다.
- 브라우저가 백그라운드이거나 랭킹 화면이 아니면 polling하지 않는다.
- 서버가 매번 외부 시세 API를 호출하지 않도록 캐시·TTL·공급자 rate limit을 적용한다.
- 장이 휴장 또는 마감이면 새 가격으로 계산하지 않고 마지막 유효 랭킹을 표시한다.
- 응답에 `updated_at`, `market_status`, `stale`, `next_refresh_at`을 포함한다.
- API 장애 시 마지막 정상 랭킹을 표시하고 `마지막 정상 갱신 시각`을 보여준다.
- 가짜 가격으로 순위를 바꾸지 않는다.

수익률 색상은 다음 위치에서 완전히 동일해야 한다.

- 시장 탐색 등락률
- 종목 상세 등락률
- 차트 기간 변화율
- 포트폴리오 총 손익·수익률
- 랭킹 수익률
- 관심종목 등락률
- 공개 포트폴리오 수익률

사용자 이름은 랭킹 표에서 모바일에서도 읽을 수 있도록 현재보다 크게 표시하고, 이름을 누르면 읽기 전용 공개 포트폴리오로 이동한다. 관리자는 랭킹과 공개 사용자 목록에서 계속 제외한다.

## 8. 관심종목 카드 정리

관심종목을 하나의 긴 문장처럼 붙여 표시하지 않는다. 각 관심종목을 독립된 카드/행으로 나눈다.

```text
관심종목        삭제
현재가
등락 금액      등락률
```

요구사항:

- 종목명은 굵고 크게 표시한다.
- 현재가는 종목명 아래 별도 줄에 표시한다.
- 등락 금액과 등락률은 한 블록으로 묶고 전역 색상 규칙을 적용한다.
- 공급자 오류나 환율 오류는 해당 종목 카드 안에서만 표시한다.
- 한 종목 오류 때문에 관심종목 전체가 사라지지 않는다.
- 모바일에서 카드 사이 간격과 터치 영역을 확보한다.
- 종목명을 누르면 종목 상세로 이동한다.

## API·권한·데이터 규칙

- 일반 사용자 응답에는 관리자 전용 코드·시세 시각·데이터 상태를 넣지 않거나 서버에서 명시적으로 제거한다.
- 관리자 권한은 서버에서 검사하며 프론트엔드의 `hidden` 속성만으로 보호하지 않는다.
- 다른 사용자의 포트폴리오 수정·주문·관심종목 삭제는 계속 차단한다.
- 시세가 오래됐거나 공급자가 실패하면 거래 체결을 진행하지 않는다.
- SQL injection 방지, 입력 검증, 세션/JWT 인증, CSRF 보호를 유지한다.
- 모든 통화·금액·수량 계산은 `Decimal`/DB `NUMERIC`을 사용한다.
